## Build + deploy workflow

Every change follows this pattern — one command builds and deploys:

```bash
source .venv/bin/activate && python3 tools/build_vX_XX.py
```

The build script:
1. Reads `daddy-duty-vX_XX.html` (previous version as source)
2. Applies patches via `str.replace(old, new, 1)` with `assert old in src` guards
3. Injects credentials from `.env` using **regex** (see warning below)
4. Writes `daddy-duty-vX_XX+1.html`
5. Copies it to `docs/index.html` + writes `docs/manifest.json`
6. Runs `node --check` to verify JS syntax (will assert/fail if broken)
7. Deploys via `git add docs/ && git commit -m 'deploy: vX.X' && git push origin main`

**Never reconstruct from scratch** — always patch the source file. Full rewrites waste context and risk losing features.

**Never edit `docs/index.html` directly** — it's overwritten on every build.

### ⚠ Credential injection — MUST use regex, not str.replace

Each build bakes real credentials into the output HTML. The *next* build reads that output as its source — so the placeholder strings are already gone. Using `str.replace` on placeholder strings silently does nothing and the old credentials stay baked in.

**Always inject credentials with regex:**
```python
import re
src = re.sub(r"const SUPABASE_URL\s*=\s*'[^']*'",
             f"const SUPABASE_URL      = '{SUPABASE_URL}'", src, count=1)
src = re.sub(r"const SUPABASE_ANON_KEY\s*=\s*'[^']*'",
             f"const SUPABASE_ANON_KEY = '{SUPABASE_ANON_KEY}'", src, count=1)
```

Same rule applies to any other value that gets baked in and needs updating in future builds.

### Starting a new version

1. Create `tools/build_vX_X.py` (copy structure from `build_v5_1.py`)
2. Set `src = open('daddy-duty-vX_X.html')` (previous version)
3. Run the scope audit (see below) before writing patches
4. Write all patches, run once

### One deploy per version — scope audit first

Before writing any patch, run a full grep audit on the source file:

1. **Count all occurrences** of what you're replacing — use `grep -c "PATTERN"` to set assertion expectations.

2. **Check for undefined JS globals** — `node --check` catches syntax, not undefined variables. If a name appears in function bodies but never in a `const/let/var/function` declaration, it's `undefined` at runtime.

3. **Bundle all patches into one script. Deploy once.**

## Debugging — "app broken / not loading"

**Step 1 is always: run the JS syntax check.** Do not investigate auth flow, cloud sync, card pools, or rendering logic until you've confirmed the JS has no syntax errors. A single syntax error crashes the entire inline script silently — nothing renders.

```bash
python3 -c "
import re
content = open('docs/index.html', encoding='utf-8').read()
scripts = re.findall(r'<script(?!\s+src)[^>]*>(.*?)</script>', content, re.DOTALL)
open('/tmp/check.js','w').write(scripts[0])
" && /opt/homebrew/bin/node --check /tmp/check.js && echo "JS syntax: OK"
```

`node` is at `/opt/homebrew/bin/node` — not in the default PATH in this environment. The build scripts use `shutil.which('node')` to find it; for manual checks always use the full path.

### Known failure pattern: premature array close in LIBRARY_CARDS

When card batches are added to `LIBRARY_CARDS`, cards must go **inside** the array — before the closing `];`, not after it. Adding cards after `];` creates a JS syntax error.

**Before adding cards, verify the array close:**
```bash
grep -n "^];" daddy-duty-vX_X.html   # find all array closes; only one should follow LIBRARY_CARDS
```

### CSS injection rule

When injecting external CSS files at build time, **always extract only the `:root {}` block.** Full CSS files contain base element rules that override inherited colors on dark-background cards.

```python
root_match = re.search(r':root\s*\{.*?\}', tokens_raw, re.DOTALL)
tokens_css = root_match.group(0)
```

### Design system assets at build time

- **CSS tokens** — read `brand/tokens/colors-and-type.css`, strip the `@import` line, insert as `<style id="design-tokens">` before the main `<style>` tag
- **Icon sprite** — read `brand/assets/icons.svg`, insert after `<body>` (it already has `style="display:none"`)

Reference icons via `<svg viewBox="0 0 24 24" width="22" height="22"><use href="#dd-mod-todo"></use></svg>`. Icon IDs use the `dd-` prefix.

## Supabase — auth + cloud sync

**Auth:** Magic link (email → click → signed in). No passwords. Works for Grant, Lauren, Katelyn.

**Schema** (run once in Supabase SQL Editor):
```sql
CREATE TABLE user_app_data (
  user_id    uuid REFERENCES auth.users PRIMARY KEY,
  data       jsonb NOT NULL DEFAULT '{}',
  updated_at timestamptz DEFAULT now()
);
ALTER TABLE user_app_data ENABLE ROW LEVEL SECURITY;
CREATE POLICY "own_row" ON user_app_data
  USING  (auth.uid() = user_id)
  WITH CHECK (auth.uid() = user_id);
```

**Sync pattern in app JS:**
- `save()` → writes localStorage immediately, then calls `debouncedCloudSave()` (2.5s debounce)
- `pushToCloud()` → upserts state JSON to `user_app_data`
- `loadFromCloud()` → on sign-in, fetches cloud data; if `updated_at` > `_savedAt` (local timestamp), calls `restoreStateFromObject()`
- `_savedAt: Date.now()` is added to every snap in `save()` for conflict resolution
- If Supabase credentials are placeholder values, the app silently runs localStorage-only
- `getSB()` guard uses `SUPABASE_URL.startsWith('https://')` — do not change this to a string comparison

**Supabase URL configuration** (required for magic links to redirect correctly):
- Authentication → URL Configuration → **Site URL**: `https://GrantBH12.github.io/daddy-duty`
- Authentication → URL Configuration → **Redirect URLs**: add `https://GrantBH12.github.io/daddy-duty/**`

## JS syntax rules — READ BEFORE WRITING ANY JS STRINGS

### 1. Apostrophes — THE most common bug

Any prose string with a contraction or possessive **will break** with single-quote delimiters.

**Rule:** card data, journal prompts, notes, any prose → always backtick template literals. Single quotes only for IDs, keys, CSS values guaranteed to contain no apostrophes.

```js
// BROKEN
'Carter's onesies'
// FIXED
`Carter's onesies`
```

### 2. Nested quotes inside template literals

```js
// BROKEN — parser chokes on ' before IBM:
`<span style="font-family:'IBM Plex Mono',monospace;">`

// FIXED — use CSS variable:
`<span style="font-family:var(--font-mono,monospace);">`
```

### 3. Verification after every patch — mandatory

Every build script already does this. To run manually:
```bash
python3 -c "
import re
content = open('daddy-duty-v5_1.html').read()
scripts = re.findall(r'<script(?!\s+src)[^>]*>(.*?)</script>', content, re.DOTALL)
open('/tmp/check.js','w').write(scripts[0])
"
/opt/homebrew/bin/node --check /tmp/check.js
```
Zero output = clean.

## Knowledge Library — Module 05

Full system documented in `daddy-duty-card-system-spec.html`. Summary below.

### Card data shape
```js
// In app (LIBRARY_CARDS):
{ id, phase, weekRange, track, tags, title, body }

// In daddy-duty-card-reference.html (CARDS) — adds:
{ certainty, sourceType, sourceLabel, sourceUrl }
```

### Phase-pool architecture

**Phase resolution** (`getCurrentLibPhase()`):
- `preparing` — no transfer date set, or transfer date is in the future
- `first` — gestational weeks 1–13
- `second` — gestational weeks 14–27
- `third` — gestational weeks 28+
- `newborn` — due date in the past

**Daily draw** (`drawCardForDate(dateStr)`):
1. Check `dailyCardLog[today]` — return cached card if exists
2. Determine phase → build filtered pool via `getPhasePool()`
3. Week-range matched + unread (priority)
4. Any unread card in pool
5. Date-seeded fallback: `pool[parseInt(dateStr.slice(-4)) % pool.length]`

### Pool filters (applied in order inside `getPhasePool()`)

All filters use a safety floor: if filtering would empty the pool, the filter is skipped.

1. **Surrogacy path gate** — remove `track:'Surrogacy'` for non-surrogacy paths (no safety floor — GC content must never show on non-GC paths)
2. **Muted tracks** — remove cards on user-muted tracks (e.g. Legal)
3. **Muted sensitivity tags** — remove cards tagged `anxiety-content` if user opted out
4. **Milestone suppression** — remove cards whose milestone tags are all in `completedMilestones`
5. **GC distance** — suppress `remote-gc` cards if `gcDistance === 'same-state'`; suppress `same-state-gc` if `gcDistance === 'different-state'`
6. **First-time parent** — suppress `first-time-parent` tagged cards if `isFirstTimeParent === false`
7. **Prior loss** — suppress `prior-loss` tagged cards if `priorLoss === false`
8. **Solo IP** — suppress `has-partner` tagged cards if `isPartnered === false`

### Tag taxonomy

**Milestone tags** (15) — suppress card when milestone logged as complete:
`pediatrician`, `daycare`, `car-seat`, `nursery`, `pre-birth-order`, `insurance`, `leave-paperwork`, `hospital-tour`, `infant-cpr`, `birth-plan`, `cord-blood`, `doc-folder`, `wills`, `announcements`, `support-network`

**Behavioral tags** — situation filters:
`has-partner`, `remote-gc`, `same-state-gc`, `prior-loss`, `first-time-parent`, `anxiety-content`, `loss-adjacent`, `birth-attendance-ip`

### Daily questions (DAILY_QUESTIONS)

18 questions. Two types:
- **Setup** (q-001–q-006, phase: preparing) — asked once to build user profile; answers set `gcDistance`, `isFirstTimeParent`, `priorLoss`, `mutedTracks`, `mutedSensitivity`, `isPartnered`, `birthAttendance`
- **Milestone check-ins** (q-010–q-021) — triggered when today's card tag matches `triggeredByTag`; confirming adds to `completedMilestones`

Selection in `getNextQuestion()`: phase-match + not answered + not skipped today → prioritize `triggeredByTag` matches → first candidate.

After any answer: `applyQuestionAnswer()` → logs to `questionLog` → applies state mutation → `save()` → `renderDailyQuestion()` → `renderHomeCard()`.
