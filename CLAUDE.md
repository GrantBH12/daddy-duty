## Build + deploy workflow

Every change follows this pattern — one command builds and deploys:

```bash
source .venv/bin/activate && python3 tools/build_vX_XX.py
```

The build script:
1. Reads `daddy-duty-vX_XX.html` (previous version as source)
2. Applies patches via `str.replace(old, new, 1)` with `assert old in src` guards
3. Injects credentials from `.env` using **regex** (see warning below)
4. Writes `daddy-duty-vX_XX+1.html`
5. Copies it to `docs/index.html` + writes `docs/manifest.json`
6. Runs `node --check` to verify JS syntax (will assert/fail if broken)
7. Deploys via `git add docs/ && git commit -m 'deploy: vX.X' && git push origin main`

**Never reconstruct from scratch** — always patch the source file. Full rewrites waste context and risk losing features.

**Never edit `docs/index.html` directly** — it's overwritten on every build.

### ⚠ Credential injection — MUST use regex, not str.replace

Each build bakes real credentials into the output HTML. The *next* build reads that output as its source — so the placeholder strings (`YOUR_SUPABASE_URL`, `YOUR_SUPABASE_ANON_KEY`) are already gone. Using `str.replace` on placeholder strings silently does nothing and the old credentials stay baked in.

**Always inject credentials with regex:**
```python
import re
src = re.sub(r"const SUPABASE_URL\s*=\s*'[^']*'",
             f"const SUPABASE_URL      = '{SUPABASE_URL}'", src, count=1)
src = re.sub(r"const SUPABASE_ANON_KEY\s*=\s*'[^']*'",
             f"const SUPABASE_ANON_KEY = '{SUPABASE_ANON_KEY}'", src, count=1)
```

Same rule applies to any other value that gets baked in and needs updating in future builds.

### Starting a new version

1. Create `tools/build_vX_X.py` (copy structure from `build_v3_4.py`)
2. Set `src = open('daddy-duty-vX_X.html')` (previous version)
3. Run the scope audit (see `workflows/new-version-checklist.md`) before writing patches
4. Write all patches, run once

### One deploy per version — scope audit first

Before writing any patch, run a full grep audit on the source file:

1. **Count all occurrences** of what you're replacing — use `grep -c "PATTERN"` to set assertion expectations. Module icons appear in home grid (plain `>0X</div>`) **and** detail headers (inline styles). Version strings appear in the brand-meta span **and** `appVersion` in `exportBackup()`.

2. **Check for undefined JS globals** — `node --check` catches syntax, not undefined variables. If a name appears in function bodies but never in a `const/let/var/function` declaration, it's `undefined` at runtime. Known historical case: `CURRENT_PHASE` (fixed v3.0 → `getCurrentPhase()`).

3. **Bundle all patches into one script. Deploy once.**

### CSS injection rule

When injecting external CSS files at build time:

**Always extract only the `:root {}` block.** Full CSS files contain base element rules (`h1, h2, h3 { color: ... }`) that override inherited colors on dark-background cards like `.todays-card` and `.lib-card`. The build already does this correctly:

```python
root_match = re.search(r':root\s*\{.*?\}', tokens_raw, re.DOTALL)
tokens_css = root_match.group(0)
```

Do not change this to inject the full file.

### Design system assets at build time

The build script injects two assets from `brand/`:
- **CSS tokens** — read `brand/tokens/colors-and-type.css`, strip the `@import` line (app already imports fonts), insert as `<style id="design-tokens">` before the main `<style>` tag
- **Icon sprite** — read `brand/assets/icons.svg`, insert after `<body>` (it already has `style="display:none"`)

Reference icons in HTML via `<svg viewBox="0 0 24 24" width="22" height="22"><use href="#dd-mod-todo"></use></svg>`. Icon IDs use the `dd-` prefix (e.g., `dd-mod-todo`, `dd-mod-budget`, `dd-attach-link`, `dd-check`).

## Supabase — auth + cloud sync

**Auth:** Magic link (email → click → signed in). No passwords. Works for Grant, Lauren, Katelyn.

**Schema** (run once in Supabase SQL Editor):
```sql
CREATE TABLE user_app_data (
  user_id    uuid REFERENCES auth.users PRIMARY KEY,
  data       jsonb NOT NULL DEFAULT '{}',
  updated_at timestamptz DEFAULT now()
);
ALTER TABLE user_app_data ENABLE ROW LEVEL SECURITY;
CREATE POLICY "own_row" ON user_app_data
  USING  (auth.uid() = user_id)
  WITH CHECK (auth.uid() = user_id);
```

**Sync pattern in app JS:**
- `save()` → writes localStorage immediately, then calls `debouncedCloudSave()` (2.5s debounce)
- `pushToCloud()` → upserts state JSON to `user_app_data`
- `loadFromCloud()` → on sign-in, fetches cloud data; if `updated_at` > `_savedAt` (local timestamp), calls `restoreStateFromObject()`
- `_savedAt: Date.now()` is added to every snap in `save()` for conflict resolution
- If Supabase credentials are placeholder values, the app silently runs localStorage-only — no auth overlay, no cloud sync
- `getSB()` guard uses `SUPABASE_URL.startsWith('https://')` — do not change this to a string comparison (previous builds clobbered it by replacing the compared string during injection)
- `initAuth()` catch block calls `showAuthOverlay()` — if auth fails for any reason the user sees the sign-in screen rather than a blank broken state

**Supabase URL configuration** (required for magic links to redirect correctly):
- Authentication → URL Configuration → **Site URL**: `https://GrantBH12.github.io/daddy-duty`
- Authentication → URL Configuration → **Redirect URLs**: add `https://GrantBH12.github.io/daddy-duty/**`

## JS syntax rules — READ BEFORE WRITING ANY JS STRINGS

### 1. Apostrophes — THE most common bug

Any prose string with a contraction or possessive **will break** with single-quote delimiters.

**Broken:** `'Carter's onesies'` — the apostrophe ends the string early  
**Fixed:** use backtick template literals for all human-readable content:
```js
`Carter's onesies wash hundreds of times`
`Worth it if you're anxious`
```

**Rule:** card data, journal prompts, notes, any prose → always backtick template literals. Single quotes only for IDs, keys, CSS values guaranteed to contain no apostrophes.

### 2. Nested quotes inside template literals

```js
// BROKEN — parser chokes on ' before IBM:
`<span style="font-family:'IBM Plex Mono',monospace;">`

// FIXED — use CSS variable:
`<span style="font-family:var(--font-mono,monospace);">`
```

### 3. Verification after every patch — mandatory

Every build script already does this. To run manually:
```bash
python3 -c "
import re
content = open('daddy-duty-v2_20.html').read()
scripts = re.findall(r'<script(?!\s+src)[^>]*>(.*?)</script>', content, re.DOTALL)
open('/tmp/check.js','w').write(scripts[0])
"
node --check /tmp/check.js
```
Zero output = clean. Any output = syntax error to fix before deploying.

## Knowledge Library — Module 05

### Phase-pool architecture
Cards are drawn from the pool matching the current pregnancy phase, derived from `dueDateStr` + `transferDateStr`.

**Phase resolution** (`getCurrentLibPhase()`):
- `preparing` — no transfer date set, or transfer date is in the future
- `first` — gestational weeks 1–13
- `second` — gestational weeks 14–27
- `third` — gestational weeks 28–40
- `newborn` — due date in the past

**Daily draw** (`drawCardForDate(dateStr)`):
1. Week-range match + unread (priority)
2. Any unread card in phase pool
3. Cycle through read cards (deterministic by date hash)

Stored in `state.dailyCardLog[dateStr] = cardId` — stable all day.

### Card data shape
```js
// In app (LIBRARY_CARDS):
{ id, phase, weekRange, track, title, body }

// In daddy-duty-card-reference.html (CARDS) — adds:
{ certainty, sourceType, sourceLabel, sourceUrl }
```

IDs: `a-001`–`a-042` (preparing), `b-001`–`b-029` (first+second), `f-001`–`f-005` (first), `s-001`–`s-005` (second), `b-030`+`t-001`–`t-013` (third), `n-001`–`n-017` (newborn).

Tracks: `Bonding | Legal | Medical | Emotional | Surrogacy | Self | Logistics`
